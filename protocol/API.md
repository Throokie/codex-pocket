# Pocket protocol v1 (implementation contract)

API base is a user-selected HTTPS server URL (debug builds may explicitly allow HTTP LAN for development). JSON error: `{error:{code,message}, request_id?}`. Native Android stores a random per-device bearer in Android Keystore protected storage; web development client keeps it only in session. Every authenticated request checks device revocation. No arbitrary RPC endpoint.

## Pairing (no device auth)

QR JSON: `{type:"codex-pocket-pair",version:1,url:"https://host",ticket:"random-one-time-secret"}`. Ticket issued only by local admin, expires in 120s. Never log QR/tickets.
POST `/pair/claim` `{ticket,device_name,client_nonce}` => `{request_id,poll_token,phrase,expires_at}`. Ticket atomically consumed; name<=80, nonce random >=16 chars. Device has NO access yet.
POST `/pair/status` `{request_id,poll_token}` => `{status:"pending"|"approved"|"denied"|"expired",phrase?,token?,device_id?,server_name?}`. Token returned only to holder of poll secret after local admin confirms exact phrase. Approved delivery idempotent for short expiry so network loss is recoverable. Native app persists credential only upon approved result. Expired/denied claim never grants access.

## Authenticated (Authorization: Bearer device token)

GET `/api/state` => `{protocol:1,revision,server:{name,version},device:{id,name},controller:{id,title}|null,threads:[{id,title,status}],messages:[{id,role:"user"|"assistant",text,images:[{id,url,mime}],created_at}],requests:[...],capabilities:{chat,images,live,approvals,user_input,interrupt},settings:{cache_limit}}`.
Messages bounded to controller last N (default30) and max total bytes; other threads only summaries. Capability false means UI explains unavailable; never creates fake actionable approvals.
GET `/api/events?after=<seq>` => SSE events `id:<revision>`, `event:update`, `data:{"revision":n}`. Heartbeat comments. Client receives event then debounced state fetch (not continuous polling). Initial snapshot authoritative after reconnect. A device revoke closes stream and subsequent API requests return401.
POST `/api/messages` `{client_id:uuid,controller_id:string,text,attachments:[media_id]}` => `{status:"delivered"|"unknown",client_id}`. The observed controller_id must match the current binding under the same write lock; stale target returns409 before dispatch. Bind nonce to immutable target/controller+body hash, reserve before external action. Unknown never blindly replayed. `delivered` means desktop accepted, not task completed. Client keeps same nonce across uncertain retry.
POST `/api/requests/<id>/answer` `{client_id:uuid,choice_id?:string,answers?:{question_id:[string]}}` => `{status:"delivered"|"unknown",client_id}`. Server binds native owner/request/turn and original available choices. Stale/replayed answer conflicts, never resumes a different request.
POST `/api/controller` `{thread_id}` => state controller. Must select known native local root, not archived or arbitrary id. Controlled per-server shared binding; settings show actual result.
POST `/api/settings` `{cache_limit:15|30|60}` => `{cache_limit}`; GET state reflects. Client theme purely local.
POST `/api/media` raw image body, Content-Type image/jpeg|png|webp|gif; max15MiB, decoded max40MP. => `{id,mime,size}`; images local trusted storage, no arbitrary path/remote fetch. GET `/api/media/<id>` returns bytes; renderer needs authenticated native image fetch or blob URL browser API. Media not cleared while pending send needs it, bounded retention cleanup documented.
DELETE `/api/cache` => `{ok:true}` clears bridge message cache but not native desktop history, unresolved requests or send dedup; native client clears its local UI cache separately.
GET `/api/devices` => `{devices:[{id,name,created_at,last_seen,current}]}` (paired owner devices only).
DELETE `/api/devices/<id>` revokes one device; current device gets pairing screen. All phone bearer devices in MVP are trusted owner devices; no sharing/untrusted guests.
GET `/health` => `{ok:true,protocol:1}` no private data.

## Local-only admin

Separate loopback listener, no CORS and no external bind. Admin access via private local capability, CSRF/Origin checks or CLI Authorization header (no query secrets). Mint QR, list pending claims with phrase, approve/deny claims, list/revoke devices. Do not expose admin through phone API/public reverse proxy. Setup instructions show supported network topology and TLS boundary.

## Android bridge (frontend integration)

Android `Pocket` JavascriptInterface (bundled content only): `request(id,method,path,bodyJson)` asynchronous callback `window.pocketResponse(id,status,bodyJson)`. Path is relative and whitelist only. Authorization added natively; never return token to JS. `getConnection()` synchronously returns `{paired,url,deviceName}` (no token). `scanPairing()` invokes native QR scanner then calls `window.pocketPairing(payloadJson)` with QR payload; `claimPairing(payloadJson,deviceName)` and `pollPairing(requestId,pollToken)` handled by JS request to pair routes; on approved native intercepts and securely stores token, strips token from JS result. `connect(url,ticket,deviceName)` optional native helper implemented consistently with UI. `disconnect()` clears secure credential; `subscribe()` delivers `window.pocketEvent(json)` updates/connection status; `unsubscribe()` closes owned stream. `pickImages()` optionally invokes file chooser (standard HTML file input supported); native shares queued via `window.pocketSharedImage(dataUrl)` or equivalent documented by Android worker. For file upload, frontend sends media body as `{base64,mime}` to native `upload(id,mime,base64)` => pocketResponse. Browser dev uses fetch raw body.

Client must show pairing/unavailable states, no mock replies in production. Remote requests cannot navigate WebView content or invoke native bridge. Normal external hyperlinks open system browser; JS interface disabled outside bundled origin.

## Pending request shape and native bridge commit (normative v1)

A public request is:
```
{id:string, thread_id:string, thread_title:string,
 type:"command_approval"|"user_input"|"question"|"desktop_only", title:string, body:string,
 options:[{id:string,label:string,description?:string}],
 questions:[{id:string,question:string,header?:string,
             options:[{id:string,label:string,description?:string}],
             is_multiple:boolean,allow_other:boolean}],
 status:"pending", created_at?:number}
```
Native owner/epoch/raw request IDs/raw decision objects stay adapter-internal. Command option IDs map to original protocol decisions; question answers contain original option labels or a user-written answer, keyed by original question ID. `desktop_only` and unknown types MUST NOT render an actionable reply button; no request payload reconstruction from chat prose. Visible request shape is versioned, not a generic arbitrary tool/RPC interface. Requests that cannot show complete review context (e.g. file approval without a diff) are `desktop_only`.

`messages[].images[]` may include `thumbnail_id`. Inline display uses the small derivative via the same authenticated media GET; opening a full image uses `id`. Every thumbnail is a distinct media ID, not a client-supplied filename. IDs may contain `-thumb`. Frontend image cache has a byte budget as well as count; no eager original-image preload.

Android bridge pairing is a coordinated two-phase local commit:
1. `preparePairing(payloadJson)` synchronously returns JSON `{url,version}` or `{error:{code,message}}`, invalidates previous candidate generation and starts a candidate. `scanPairing()` does the same validation then invokes `window.pocketPairing(payloadJson)`.
2. JS uses `request` to claim and poll. Native binds claim/status to candidate origin, generation, request_id and poll secret. On current approved status Native tentatively stores Keystore credential, strips token and returns approved. It retains previous credential solely until local commit/cancel.
3. JS transport verifies its candidate epoch/origin/request_id before accepting approved, calls `finishPairing()` and then refreshes connection. Native commit discards previous credential; neither JS nor sessionStorage receives the Android token.
4. Cancel, starting another pairing, or disconnect calls `cancelPairing()` before replacing candidate. If approved arrived and was tentatively stored but not committed, Native restores the preceding valid credential (or unpaired state). Old late status can never re-save it. `disconnect()` additionally clears active credential and stops streams.
5. Ordinary HTTP and stream callbacks also bind captured connection identity. A late old 401 cannot delete a new credential or emit an unauthorized event for the new service. Old successful state cannot be saved under another service's cache key.

`getConnection()` returns `{paired,url,deviceName,backgroundEnabled?,notificationsGranted?}` only, never token. Native `subscribe()` delivers `pocketEvent` JSON of `connected`, `update`, `disconnected`, `unauthorized` (and explicit local settings/error events). Each stream callback is generation checked natively. Background notifications use at most one in-flight state fetch plus one dirty follow-up, not an unbounded queue. Canceled/unsubscribed streams cannot signal new connection state. Clearing local content and changing service must release temporary image URLs and bound caches.

For a definite no-dispatch rejection, HTTP409 with `error.code` distinguishes `controller_changed`, `stale_request`, `thread_busy`, `unsupported`, etc. Such nonce is rejected in the ledger; repeating it does not dispatch. Network-timeout/unknown is never automatically replayed. `delivered` remains acceptance, not task completion.

Async question source is exactly `agentMessage.questions`, ID `JSON.stringify(["request_user_input_async", item.id,index])`. The phone never invents buttons from prose. Replies use the existing owner native idle start-turn with the exact XML user-reply envelope; no model/mode/permission override. An active or unknown thread returns thread_busy before dispatch. Accepted user-message evidence, not RPC ack, clears the pending card. This path is separate from native requestUserInput responses and command approval decisions.

## v1 additive network routes (App 0.2.0)

`GET /identity?challenge=<64 lowercase hex>&origin=<URL encoded canonical candidate origin>` is public and MUST NOT receive a Bearer token. Returns `{protocol:1,server_id,public_key,challenge,origin,signature}`. `server_id` is lowercase SHA256 of the P256 public key DER SPKI; key/signature are standard Base64. Signature is ECDSA SHA256 DER over exact UTF8 `codex-pocket-route-v1\n{challenge}\n{server_id}\n{origin}` (no final newline). Only origins registered through the separately authenticated local admin are signed; unknown origin is403 `route_unregistered`. Origin scheme/hostname lowercase, IDNA host ASCII, compressed IPv6 brackets, default ports omitted, no path/trailing slash/userinfo/query/fragment/zone IDs. Nonce mismatch, origin mismatch, pin mismatch or signature failure MUST prevent sending credentials. This signature is not channel encryption: production TLS certificate validation and redirect rejection remain mandatory.

Local-only admin `POST /admin/networks` body `{endpoints:[{url,label,kind}],allow_http?:bool}` registers1–6 routes; kind one of lan/tailscale/private/public, label≤40 characters, URL≤600, total configured endpoint JSON≤1700 bytes. `POST /admin/pair` accepts the same list plus primary `url`; returned QR adds `server_identity:{id,key,algorithm:'p256-sha256'}` and `endpoints`. `/pair/status` also includes identity/endpoints. A pinned QR must verify the original origin before claim and retain the QR pin through final approval. Legacy unpinned QR remains single-origin and cannot self-upgrade from an unauthenticated identity response.

Android bridge additions: `getNetworkStatus()` returns JSON `{supported:true,mode:'auto'|'manual',active_url,endpoints:[{url,label,kind,status:'available'|'unreachable'|'identity_mismatch'|'unverified',latency_ms?,active}],probing,error?}`; `configureNetworks(id,configJson)` async response and `probeNetworks(id)` async response use existing pocketResponse. Config is `{mode,manual_url?,endpoints:[...]}`. Responses are bounded and guarded against pairing-generation changes. `pocketEvent({type:'network'})` signals local route status change, not a new logical pairing; `getConnection().url` stays logical origin and `active_url` is separate. No access token crosses JS. Browser fallback reports unsupported instead of pretending to perform native routing.

Routing must not replay POST/DELETE/uploads or alter original client IDs after a lost receipt. All foreground/background/API/SSE/media paths share one process-wide route policy; old probe results cannot select a route for new credentials. One GET may retry once after verified failover. A successful identity response never expands the configured candidate list. With any HTTPS candidate automatic mode excludes cleartext HTTP; release rejects HTTP outright.

HTTP application errors (including500/502/503/504/429) are returned unchanged and never alone invalidate transport health or trigger retry. Only a non-service-revocation gateway401 follows the HTTP route-failure branch; actual transport exceptions retain the bounded GET recovery. SSE application HTTP errors use bounded stream backoff and never directly fail a route.

## v1 additive automatic discovery (App 0.3.0)

New QR payload preserves the existing `type`, `version:1`, `url`, ticket and `server_identity`, and adds `discovery:{version:1,enabled:true,tls_spki:<lowercase SHA256 hex of TLS DER SPKI>,service_type:'_codexpocket._tcp.',revision:<integer>}`. QR endpoints are at most three bounded bootstrap seeds; the authenticated signed manifest supplies the full list (at most six). A failed primary seed may try another explicitly authorized seed. Legacy QR has no discovery authority and requires a new scan to enable it.

Public `GET /discovery?challenge=<64 lowercase hex>` MUST NOT receive Bearer. Response is `{protocol:1,server_id,challenge,payload:<exact JSON string>,signature:<Base64 DER ECDSA-SHA256>}`. Signature input is exact UTF8 `codex-pocket-discovery-v1\n{challenge}\n{server_id}\n{payload}` with no final newline. Verify the exact payload bytes using the QR P256 identity key before parsing/adopting it. Payload is `{version:1,revision,endpoints:[...],tls_spki,service_type}`. Validate challenge, expected server identity, TLS SPKI, version, monotonic revision and bounded endpoint fields before replacing managed routes. Replay, malformed/oversized manifests or pin/signature mismatch cannot expand trust.

Endpoint additions are `managed:boolean,source:'auto'|'manual',tls:'pinned'|'system'`. Auto private addresses use QR-pinned TLS SPKI; computer-registered manual routes use system TLS. mDNS announces `_codexpocket._tcp.local.` with public TXT `id`, `v=1`, `tlsport` and a TLS port. Android NSD may use resolved addresses as temporary discovery transports only; a matching TXT/name is insufficient. Never adopt an NSD relay address into managed endpoints unless independently present in the verified manifest. Discovery must not send credentials before verification, terminate TLS at an untrusted discovery relay, or replace the logical pairing URL.

Local admin `GET /admin/state` adds `discovery:{enabled,state:'ready'|'partial'|'unavailable',diagnostics:[safe string],revision,last_scan?,endpoints,tls_port?}` and `manual_endpoints`. `POST /admin/pair` `{auto:true,manual_endpoints?:[...]}` generates a QR without user-supplied URL; absent usable addresses returns a real error. `POST /admin/networks` `{auto:true,manual_endpoints:[...]}` changes optional computer-managed addresses; `POST /admin/discovery/refresh` `{}` rescans local addresses. Admin automatic rows are read-only; optional manual rows remain editable. With discovery disabled/missing, admin uses `{auto:false,url:<first>,endpoints:[...],allow_http?}` for pairing and `{auto:false,endpoints:[...],allow_http?}` for saving, with at least one manual address. Admin listener remains loopback-only.

Android `getNetworkStatus()` additionally returns `auto_sync`, `discovery_supported`, `discovery_state:'disabled'|'idle'|'syncing'|'searching'|'ready'|'error'`, `last_sync?:<Unix milliseconds>`, `revision?:integer`, `discovery_error?:string`; endpoints retain managed/source/tls metadata. `configureNetworks` accepts `auto_sync:boolean` and preserves validated managed metadata; native rejects forged managed trust. All managed rows remain read-only on the phone even when sync is off. Local extras use manual/system and the combined list remains bounded to six. `probeNetworks` triggers discovery plus route detection; `pocketEvent({type:'network'})` only refreshes real local status, without changing credential epoch or drafts. Browsers do not implement NSD and report this capability unavailable. `discovery_supported` means QR-authorized identity and TLS pin are complete, not guaranteed current reachability. State and SSE updates may add `discovery_revision` to trigger bounded synchronization.

## App 0.3.1 ADB files

Separate local shell interface; no network API or approval bypass. `io.github.codexpocket.app/.AdbCommandReceiver`, action `io.github.codexpocket.app.ADB_COMMAND`, manifest permission `android.permission.DUMP`. Extras: `command` init/status/import-pairing/import-image/reset-history, `request_id` ASCII alnum/underscore/hyphen ≤64; import `file` strict ASCII basename≤100, no `..`. Root is `getExternalFilesDir(null)/CodexPocket` with inbox/outbox/media. Pairing≤64KiB, image≤12MiB plus actual format and dimension checks.

Atomic receipts `outbox/result-<request_id>.json` and `status.json` contain version1, request_id, command, status ok/queued/prepared/error, fixed code, updated_at, paired and history counts/epoch where applicable. No token, ticket, payload, chat or key export. `prepared` is preview/draft completion, not authorization/upload/delivery. Init/status do not need Activity. Imports may launch the bundled Activity through a private pending entry; they never pass caller-controlled raw payload through the exported Activity intent.

Import IDs use `e<current_epoch>-<id>`; init/status reveal epoch without consuming the 512 import-ledger capacity. Same ID/content does not repeat preparation; changed content conflicts. Reset requires no in-flight import, atomically increments epoch and clears terminal import ledger/staging, never credential/draft/media state. Old epoch IDs are rejected; reset retry does not increment twice. Interrupted processing is delivery_unknown with no automatic replay; expired stages are bounded and reclaimed during later command checks. See docs/ADB_FILES.md for CLI and platform limits.

## Server 0.3.3 refresh delivery

Refresh notifications use a single worker with a trailing pending bit at adapter and Hub layers. Controller native message/state bursts schedule one resettable quiet-window reconciliation, at most three tail refreshes after quiet (.6/1.5/3 second intervals), canceled on controller change/close. Projection generations reject stale reads; unknown message schema retains cached content and reports error. This never replays a message or decision. Local authenticated admin/state adds delivery revision, opaque cached message IDs and subscriber count; no raw messages or credentials are exposed by that diagnostic field.

## App/server 0.4.0 configuration invitations and interface selection

Local admin `POST /admin/config-link {}` returns `{link,qr_data_url,bootstrap,...bootstrap}`; `{rotate:true}` replaces the invitation. URI is `codexpocket://import#v1.<unpadded base64url UTF8 JSON>`, max2400 bytes. Bootstrap `{type:'codex-pocket-config',version:1,name,config_id:<64 lowercase hex>,server_identity,discovery,revision,url,endpoints}` contains at most3 explicit HTTPS+pinned seeds, no device token or pairing ticket. Name is an unverified label; preview and admin display the same short identity/SPKI fingerprints. Invitation ID is not a device grant and cannot authenticate `/api/*`.

Public `GET /config/{config_id}?challenge=<64 lowercase hex>` returns a bounded signed public profile; explicit new-device import uses `POST /config/{config_id}/pair {challenge}` directly, avoiding an extra profile round trip. Both return `{protocol:1,server_id,challenge,payload:<exact JSON string>,signature}`. ECDSA-SHA256 DER/Base64 signs UTF8 `{prefix}\n{challenge}\n{server_id}\n{payload}` without final newline. GET prefix is `codex-pocket-config-v1`, pair prefix `codex-pocket-config-pair-v1`. Signed payload binds config_id, identity, discovery/TLS pin, revision and fullHTTPS endpoints≤6. Pair payload additionally has `type:'codex-pocket-pair'`, short-lived ticket and expires_at (Unix seconds). Verify expected ID/challenge/key/pin/domain/version/revision/expiry before preparing the existing claim flow. A nonce adds freshness, never authority to change trust. Neither profile nor ticket mint creates a device; original phone claim and local phrase approval are mandatory.

Rotation atomically denies old linked issued/pending pairings and clears their token envelopes; approved devices remain active. Same invitation is reused without rotation, and admin state exposes only invitation metadata, not its ID. Validated sources/global/link request budgets and per-link/global active-ticket caps apply. Invalid IDs remain source-limited but do not consume global mint budget. Legacy database migration adds nullable pairings.config_id; old unlinked invitations remain compatible.

`previewConfigLink(raw)` synchronously returns public parsed config, including server_identity/discovery, already_paired/requires_pairing/different_server, without network or credential change. `window.pocketConfigLink(raw)` (scan/deep link) only opens preview. Explicit “导入并连接” calls async `importConfigLink(id,raw)`; same paired service returns `{already_paired:true,network_status}`, otherwise `{already_paired:false,pairing}`. The same click authorizes subsequent claim, never computer approval. New service retains the previous grant until existing two-phase local commit. Close/Back/Escape/mask immediately cancel native scope and candidate plus JS pairing generation; stale callbacks cannot reopen UI or commit routes. New links cannot replace an in-flight import/pairing. No raw URI fragment or payload logging.

Admin discovery status adds detected_interfaces `[{name,addresses,excluded}]` and excluded_interfaces. `POST /admin/discovery/preferences {excluded_interfaces:[name...]}` accepts at most32 validated interface names and persists preference. CLI `--exclude-interface` repeats the same setting. Exclusion removes matching automatic listener/announcement/signed endpoints and suppresses manual entries at those detected IPs without deleting operator configuration; it does not forbid all10/8 addresses. App settings display active_url or friendly server status; logical getConnection.url remains an internal stable identity/cache key.
