# 桌面平台：实现与验收分开

本页描述 `cross-platform-foundation` 开发分支。已发布的 0.4.0 APK与服务端仍按原来的 Android + Linux 范围提供，不因这个分支新增代码而变成三平台成品。Android 手机通过电脑上的服务访问 Codex；服务必须与 Codex 桌面同宿主、同用户运行。

| 电脑平台 | 安装（wheel） | 服务启动 | Codex 桌面连接 | 实机端到端 |
| --- | --- | --- | --- | --- |
| Linux | CI 安装验证：Python 3.11 / 3.14 | CI 无桌面冒烟通过 | 沿用原实现；0.5.0rc1 未重新实机验证 | 沿用 0.4.0 记录 |
| macOS | CI 安装验证：Python 3.11 / 3.14 | CI 无桌面冒烟通过 | 已实现，未实机验证 | 本轮不进行 |
| Windows | CI 安装验证：Python 3.11 / 3.14 | **不支持，启动即拒绝** | **不支持** | 不适用 |

证据：[三平台安装 CI](https://github.com/Throokie/codex-pocket/actions/runs/40473459493)，源码提交 `c086fe3c51cf48c180027047fc02b02909f5d9f4`。六个安装 job 全部通过，macOS/Windows 均为 GitHub runner，不是用户真实 Codex 桌面。候选发行附件以其发行说明所列最终构建为准。

**安装成功、单元测试或 CI 通过都不等于桌面平台验收。** Windows 可以安装包、运行 `doctor`，但 `codex-pocket serve` 在创建私有状态前返回退出码 3。安装不代表服务可用。

本轮根据“能安装”的范围决定，不安装、启动或登录真实 Codex 桌面，不进行新的真实握手和收发验收。macOS 桌面适配基于 Unix socket；CI 仅验证无桌面时的安全启动与能力关闭，不证明与真实 Codex 桌面兼容。

0.4.0 原有 Linux 证据：2026-10-26，一台 Android 16 手机覆盖安装保留配对，关闭 Wi-Fi 后经蜂窝/Tailscale 读取 Linux 总控和聊天状态；早期文字、图片识别和消息更新另有记录。原记录未完整留下 Linux 发行版和桌面版本，本轮不补猜，也不扩大为所有操作已验。

安装方法见[安装候选包](INSTALLATION.md)，各系统结果以[安装工作流](https://github.com/Throokie/codex-pocket/actions/workflows/installable-package.yml)的对应提交为准。

## macOS 当前差异

- 原有 Unix socket 同用户、文件类型和父目录权限检查保留；默认仍使用 `$CODEX_HOME/ipc/ipc.sock`（未设时为 `~/.codex/ipc/ipc.sock`）。该默认路径尚未经过真实桌面握手确认。
- 不截断长 socket 路径。长度是否可用由操作系统判断，失败映射为不包含本机路径的连接错误；不自动换端点或改用 TCP。
- 本分支尚未实现 macOS 自动局域网枚举，不执行 Linux 的 `ip` 命令。管理页会提示这一缺口；可先在电脑管理页登记可达地址。
- Tailscale 仍只查询本机状态，不获取其他设备或账号资料。CLI 不在 PATH、未运行或旧版本不支持参数时，会给出诊断，不承诺自动恢复。
- 管理页启动使用系统 `open`；Linux 继续使用 `xdg-open`。管理链接不打印到终端。

## Windows 为什么仍拒绝启动

实际 Codex 桌面 IPC 端点、协议兼容性和对端身份检查尚无现场证据。私有文件还需要 Windows ACL 方案；POSIX 权限位不能替代它。平台门同时位于命令行和 Store，直接构造服务也不能跳过。

本分支没有加入命名管道实现、裸 TCP IPC、第二个模型执行器或审批绕过。若继续 Windows 适配，需要先在实际运行的 Windows Codex 上核对端点和身份边界，再实现与验证。

## 私有文件保护的变化

新建私有目录先核当前用户属主，并拒绝最后一级为符号链接；父路径中的符号链接不检查（例如 macOS 的 `/var` → `/private/var`）。属主正确但权限过宽的数据目录会被收紧到 0700，不会被拒绝。新文件以排他、不跟随符号链接和 0600 权限创建，覆盖管理链接采用同目录临时文件原子替换。

现有身份/TLS密钥只校验，不重写。数据库先以 0600 创建，SQLite 的 WAL/shm 也检查权限；不临时修改进程全局 umask。

Linux 用户从 0.4.0 升级后，启动时会额外检查：数据目录及其中密钥、数据库（含 `-wal`/`-shm`）必须属于当前用户，且文件不向组或其他用户开放；不满足时拒绝启动，错误文本不含密钥或管理链接。排查：`ls -ld <数据目录>`、`ls -l <数据目录>`、`stat <报错文件>`，确认属主为运行服务的用户、文件权限为 `-rw-------`。数据目录最后一级不能是符号链接，请将 `--data` 指向真实目录。升级前备份数据库、身份与 TLS 密钥。不要批量 chmod、删除密钥或清库来让检查通过；属主不符通常说明换了运行用户或数据目录指错了。

## 只读现场探针

```sh
python3 scripts/platform-probe.py
```

探针仅收集平台/Python版本、有限的安装位置与进程名、socket或管道名称等元数据，不连接 IPC、不读取配置正文或凭据、不创建文件。输出不是支持证明；个别平台组件不可读时保留未知状态。

输出可能包含本机接口和管道名称，公开分享前请自行核对并脱敏。

真实桌面验收应在可使用的独立测试聊天里分别验证握手、会话目录、跟随、文字/图片、异步问题及断线恢复。原生命令审批必须另有真实触发和核销证据。
